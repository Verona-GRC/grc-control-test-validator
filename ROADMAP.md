# Project Roadmap

## GRC Control Test Validator

This roadmap outlines the planned development of the GRC Control Test Validator from a basic control-testing prototype into a more capable, evidence-driven GRC assurance tool.

## Phase 1 – Working Prototype (Completed)

- Develop a Python-based control testing script.
- Create fictional deployment and approval records.
- Define testing criteria for production deployment approvals.
- Implement Pass, Fail and Inconclusive result classifications.
- Generate a structured CSV results report.
- Document the control test plan, testing methodology, test cases and audit findings.
- Create automated Python tests using the unittest framework.
- Verify six defined test scenarios, with all six tests passing.

## Phase 2 – Improved Testing and Reporting (Planned)

- Introduce additional evidence completeness and data-quality checks.
- Improve exception identification and tracking.
- Strengthen input validation and error handling.
- Expand test scenarios to cover additional evidence conditions.
- Improve the structure and usability of generated reports.
- Support clearer audit observations, recommendations and follow-up actions.

## Phase 3 – Expanded Control Coverage (Planned)

- Introduce additional security and GRC control tests.
- Develop configurable testing criteria.
- Support testing across multiple control environments.
- Improve traceability between control requirements, evidence and test results.
- Establish reusable testing logic for different control types.

## Phase 4 – AI-Assisted GRC Capabilities (Exploratory)

- Explore AI-assisted evidence interpretation.
- Support the identification of potential control gaps and anomalies.
- Generate draft audit observations and recommendations.
- Distinguish between evidence-based findings and AI-generated suggestions.
- Require human review and approval before finalising AI-assisted outputs.

## Phase 5 – Source-System Evidence Integration (Future Development)

- Explore integration with relevant source systems.
- Retrieve evidence directly from authorised systems where technically feasible.
- Improve evidence traceability, integrity and auditability.
- Reduce reliance on manually prepared evidence files.
- Consider access controls and secure handling of retrieved evidence.

## Development Principles

The project will prioritise:

- Evidence-based testing and validation.
- Consistent and repeatable results.
- Clear explanations of exceptions and limitations.
- Traceability between control requirements, evidence and results.
- Human oversight and professional judgement.
- Responsible use of AI and automation.
- Security and appropriate access to evidence.

## Current Status

The project is a working, rule-based prototype using fictional CSV data. Phase 1 is complete. All subsequent phases are planned or exploratory enhancements and have not yet been implemented.

The project is intended as a learning and portfolio prototype, not a production-ready GRC platform.
